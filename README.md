# Сводка поддержки

Небольшое интерактивное демо тестового задания Руссмаркет: четыре случая,
раздельные источники, приоритеты и конкретные следующие действия.

Исходный код: https://github.com/balkhaev/demo-test
Демо: https://demo.balkhaev.com
Код и объяснение: https://demo.balkhaev.com/#code

## Как устроено

- `dist/data.js` — исходные примеры. Дата 19 октября 2026 года выбрана только
  как фиксированный понедельник для демонстрации; в задании календарная дата не дана.
- `dist/engine.js` — чистая функция `buildSummary(cases)`. Правила не обращаются
  к сети, языковой модели, базе данных или текущему времени.
- `dist/prompt.txt` — применимая к новым данным инструкция для ИИ и контракт извлечения.
- `test/engine.test.mjs` — проверки значимых переходов и противоречий.

Демонстрационные сведения из сообщений структурированы вручную. Изменение свободного
текста само по себе не запускает извлечение смысла: правила используют поле `signal`.
Показанный в интерфейсе код — тот же модуль, который пересчитывает сводку.

## Открыть и разместить

Переносимый `Russmarket_Demo.html` открывается как обычный файл: все данные, стили,
исполняемый код и скачиваемый архив проекта находятся внутри. Раздел «Как это устроено»
показывает настоящие исходники. Кнопка «Скачать проект» сохраняет этот архив.

Приложение `demo-test` размещено в Coolify на `https://demo.balkhaev.com`.
Контейнер собирается из Dockerfile и отдаёт содержимое `dist/` через nginx на порту 80.
DNS домена уже указывает на сервер; HTTPS и статус `running:healthy` проверены.
Все шесть опубликованных файлов совпадают по SHA-256 с проверенными исходниками.
Визуальная проверка в браузере пока не выполнена: управление браузером недоступно.

В размещённой версии кнопка «Скачать проект» ведёт на архив ветки `main` этого
репозитория; переносимая HTML-версия содержит собственный архив исходников.

Повторная сборка переносимой версии из проекта:

```sh
python package-demo.py
node build-demo.mjs
```

HTML появится в родительской папке. Это упаковка файлов, без установки зависимостей.

## Проверка

Требуется Node.js с поддержкой встроенного test runner и ES-модулей:

```sh
node --test test/engine.test.mjs
```

11 тестов проверяют исходный порядок, разделение источников, неполные документы,
подтверждение руководителя без завершения увольнения, приёмку после задержки,
недостачу, противоречия и сохранность входных данных. Предыдущая сводка сохраняет
свой снимок CRM и переписки при редактировании данных до следующего пересчёта.

## Первый запуск с реальными данными

Каждый рабочий день в 10:00 решение получает разрешённую выгрузку CRM и сообщения
из связанных рабочих чатов, сопоставляя их по ID случая. Сводка появляется в рабочем
канале support-отдела со ссылками на исходные записи и сообщения, а неоднозначные
соответствия передаются на ручную проверку. Перед действием сотрудник проверяет
актуальность записи, автора сообщения и обязательные подтверждения. Первую неделю
сводка работает параллельно с ручной проверкой: вместе с отделом разбираются пропуски,
лишние задачи и ошибки приоритетов. Время подготовки списка дел и доля выявленных
срочных случаев сравниваются с ручным процессом; переход к регулярному использованию
возможен при экономии времени без пропуска критичных задач на проверенной выборке.

## Границы демо

CRM, рабочие чаты и LLM не подключены. Автоматические изменения CRM и отправка
сообщений не выполняются. Правила рассчитаны на три типа операций из задания;
неизвестный тип вызывает явную ошибку. Для реальной интеграции нужно проверить
права доступа, полноту выгрузки, сопоставление ID, время сообщений и качество
извлечения; экономия времени на работе support-отдела пока не измерена.
